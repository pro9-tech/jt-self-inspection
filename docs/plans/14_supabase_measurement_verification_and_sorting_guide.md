# 14. 수파베이스(Supabase) 계측 기록 저장 검증 및 정렬 가이드

## 1. 개요 및 조사 결과
- **현상 보고**: 구글 시트와 Supabase의 'Weight Measurement(중량)'는 저장이 잘 되는데, 'Other Measurements(그 밖의 계측기록)'는 저장이 안 되는 것으로 보임.
- **실제 DB 확인 결과**:
  - 실제 Supabase 데이터베이스 조회 결과, **오늘(2026-10-02) 오전 10:16 및 10:20에 등록된 'Other Measurements' 기록(캡 충진1 등 3건, id 795, 796, 797)이 이미 정상적으로 100% 저장**되어 있습니다!
- **저장이 안 된 것처럼 보였던 근본 원인**:
  1. Supabase 대시보드(Table Editor)의 기본 정렬 기준이 `id` 오름차순(과거순)으로 되어 있습니다.
  2. `Other Measurements` 테이블은 전체 데이터 수가 **797건(총 8페이지)**에 달하여, 1페이지(`Page 1 of 8`)에는 과거 데이터(2026-08-10 등 최초 100건)만 표시됩니다.
  3. 반면 `Weight Measurement` 테이블은 총 데이터 수가 **78건**에 불과하여, 1페이지(100건 제한) 내에 오늘 최신 데이터가 바로 눈에 띄었던 것입니다.

---

## 2. 해결 및 조치 방안
1. **Supabase 대시보드에서 최신 데이터 확인 방법**:
   - 방법 A: 대시보드 상단 `Sort` 메뉴에서 `id` 또는 `created_at` 컬럼을 **Descending (내림차순)**으로 정렬.
   - 방법 B: 대시보드 하단 페이지네이션에서 `>` 화살표를 눌러 **마지막 페이지(Page 8)**로 이동.
   - 방법 C: 상단 검색 필터(`Filter by...`)에 오늘 날짜 `2026-10-02`를 입력하여 조회.
2. **코드 안정성 개선**:
   - `syncToSupabase`에서 `Weight Measurement` 및 `Other Measurements` 저장 시 에러가 발생할 경우 명확히 에러 메시지를 전달할 수 있도록 로깅 및 예외 처리 강화.
   - 로컬 개발 환경용 `.env` 파일 구성.
