# 13. 계측 테이블 항목별 올 오어 나씽(All-or-Nothing) 유효성 검사 개선 계획서

## 1. 개요 및 목적
- **목적**:
  1. 계측 테이블 저장 필수 조건 강화:
     - 최소 하나의 항목은 반드시 3개 전체가 입력/선택되어 있어야 함.
     - 그 외의 모든 항목은 **아예 비어있거나(0개)** 또는 **3개 전체가 꽉 차 있는 경우(3개)**에만 저장을 허용.
     - 1개 또는 2개만 선택/입력된 항목(불완전 항목)이 단 하나라도 존재할 경우 저장을 거부함.
  2. 불완전 항목 존재 또는 3개 꽉 찬 항목 부재로 저장 거부 시:
     - 메모장은 펼치지 않고 그대로 닫아둠.
     - 해당 행의 모든 선(테두리 및 세로 구분선)을 빨간색으로 표시.
  3. 모든 기존 연동(구글 시트, Supabase) 및 UI 디자인 시스템 완벽 유지.

---

## 2. 세부 검증 조건 명세
1. **항목별 입력 개수 판별 함수 (`getCategoryFilledCount`)**:
   - 3개 샘플 슬롯 중 유효한 값(null, undefined, 빈 문자열 제외)의 개수를 0~3 사이로 계산.
2. **저장 허용 조건**:
   - `hasAtLeastOneFullCategory`: 채워진 개수가 3개인 항목이 최소 1개 이상 존재.
   - `!hasPartialCategory`: 채워진 개수가 1개 또는 2개인 항목이 0개 (존재하지 않음).
   - 즉, 모든 항목의 채워진 개수는 `0` 또는 `3`이어야 하며, 적어도 하나는 `3`이어야 함.
3. **거부 시 동작**:
   - `setShowError(true)`로 행 전체 빨간 테두리 표시.
   - 메모장은 펼치지 않음 (`isExpanded` 변경 없이 return).
4. **부적합 메모 검사**:
   - 3개 채워진 항목 중 부적합 판정이 있는 항목이 있다면, 해당 항목의 메모가 작성되어 있어야 통과. 메모 누락 시 메모장을 열고 빨간 테두리 표시.
